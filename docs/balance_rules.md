## 目的

这份文档用于记录当前原型的数值平衡口径，尤其是“耗势”与招式收益之间的约束关系。

适用范围：

- 字符版战斗原型
- 视觉版战斗原型
- 当前 `CardData` 结构下的基础卡牌设计

对应实现位置：

## 核心原则

当前原型把每张基础牌的强度，先压缩成一个统一的“效果预算”。

预算定义如下：

```text
效果预算 = 增己势 * 2 + 削敌势 * 2 + 伤害 + 格挡
```

基础平衡约束如下：

```text
增己势 * 2 + 削敌势 * 2 + 伤害 + 格挡 = 耗势 * 4
```

也可以写成：

```text
效果预算 = 耗势 * 4
```

这也是当前代码里 `CardData.effect_budget()` 的口径。

## 为什么这样设计

这样做的目标，是让三类基础收益能共用同一把尺子：

- 势收益
- 直接伤害
- 防御收益

在当前原型里：

- `1` 点增己势，按 `2` 点预算计算
- `1` 点削敌势，按 `2` 点预算计算
- `1` 点伤害，按 `1` 点预算计算
- `1` 点格挡，按 `1` 点预算计算

因此，势类效果被认为比等值的伤害或格挡更“贵”，因为它会影响后续回合出招能力、崩势判定和节奏优势。

## 基础卡的配表公式

设计一张基础牌时，先定耗势，再反推可用预算。

### 耗势 1

```text
预算 = 4
```

可接受的例子：

- 增己势 2
- 削敌势 2
- 伤害 4
- 格挡 4
- 伤害 2 + 削敌势 1

### 耗势 2

```text
预算 = 8
```

可接受的例子：

- 伤害 8
- 格挡 8
- 增己势 2 + 伤害 4
- 削敌势 2 + 格挡 4
- 增己势 1 + 削敌势 1 + 伤害 4

### 耗势 3

```text
预算 = 12
```

可接受的例子：

- 伤害 12
- 增己势 2 + 伤害 8
- 削敌势 2 + 伤害 8
- 伤害 4 + 格挡 8

### 耗势 4

```text
预算 = 16
```

这类牌通常已经接近高爆发、终结或多功能牌的范围，应该慎用。

## 当前默认设计取向

虽然公式允许自由拼装，但当前原型仍然建议保持“主效果明确”。

基础牌优先分成三种：

- 势牌：以增己势 / 削敌势为主
- 伤害牌：以直接伤害为主
- 格挡牌：以格挡为主

基础牌的设计建议：

- 一张牌最好只有一个主效果
- 低耗势牌优先突出单一定位
- 多效果叠加尽量留给更高耗势牌

这能让玩家更容易读懂牌意，也有利于验证先后手、距离与势系统本身，而不是让数值组合把原型复杂度抬得太快。

## 距离与标签暂不直接计价

当前基础预算公式里，没有把这些项单独折算进预算：

- 距离区间宽窄
- 起手 / 追击 / 终结标签
- 先机标签
- 藏招
- 连招衔接价值
- 预览可见性差异

原因不是它们不重要，而是当前原型阶段优先先把“基础数值骨架”固定下来。

因此，当前建议是：

- 先用公式约束裸数值
- 再用标签和职业关系做微调
- 如果某张牌因为标签优势明显过强，优先削数值，不先改公式

## 什么时候允许偏离公式

以下情况可以允许少量偏离，但需要明确写原因：

- 明确的职业签名牌
- 连招起手牌，为了保证套路能启动
- 终结牌，为了形成明确的爆发终点
- 奖励牌 / 特殊节点牌 / 精英掉落牌
- 仅用于测试某个机制的实验牌

允许偏离时，建议遵循：

- 先标注“为什么偏离”
- 偏离只集中在一两个测试点，不要整套牌一起漂移
- 若偏离是因为机制收益太高，应优先给出限制条件，而不是无上限堆数值

## 当前实现里的程序口径

代码中的预算函数是：

```text
effect_budget = gain_momentum * 2 + break_momentum * 2 + damage + guard
```

这表示程序层已经把四类基础收益视作统一预算项。

但目前程序还没有自动拦截“不满足公式”的卡牌。

也就是说：

- 公式已经是设计规则
- 但暂时还是靠策划配表时自检，而不是运行时报错

## 配表时的检查步骤

每次新增或修改基础牌，建议按下面顺序检查：

1. 先写出耗势。
2. 计算目标预算：`耗势 * 4`。
3. 把增己势、削敌势、伤害、格挡折算成统一预算。
4. 检查是否正好等于目标预算。
5. 如果不相等，先判断是不是“特例牌”。
6. 如果不是特例牌，就把数值收回公式内。

## 简单例子

### 例 1：纯伤害牌

```text
耗势 2
伤害 8
```

计算：

```text
0*2 + 0*2 + 8 + 0 = 8
耗势*4 = 2*4 = 8
```

满足约束。

### 例 2：势牌

```text
耗势 1
增己势 2
```

计算：

```text
2*2 + 0 + 0 + 0 = 4
耗势*4 = 1*4 = 4
```

满足约束。

### 例 3：混合牌

```text
耗势 2
削敌势 1
伤害 6
```

计算：

```text
0 + 1*2 + 6 + 0 = 8
耗势*4 = 8
```

满足约束。

### 例 4：超模例子

```text
耗势 1
伤害 5
```

计算：

```text
0 + 0 + 5 + 0 = 5
耗势*4 = 4
```

超出 1 点预算。

如果它不是故意做成特例牌，就应该回调到：

- 伤害 4
- 或增加额外成本 / 条件

## 推荐补充项

后续如果开始把原型推进到更完整的表驱动版本，建议再补两类规则：

- “特例牌预算规则”
- “职业修正系数”

现阶段先保持基础公式简单、稳定、可手算，价值最高。
